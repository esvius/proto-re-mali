# Открытые проблемы

## #1 Хук `core::Report` (rva 0x0063c750) коррелирует с 60-секундным ожиданием критической секции
Симптом (Wine 11.20 + DXVK): `err:sync:RtlpWaitForCriticalSection section 11315750 ... retrying (60 sec)`,
фоновый поток ждёт секцию, которую держит главный поток. Игра при этом каждый раз доходит до главного меню.

Статистика запусков по 75–85 с:
| Режим | С ожиданием |
|---|---|
| без хуков (`PROTORE_NOHOOKS=1`) | 0 / 3 |
| те же байты записаны обратно (`PROTORE_NULLPATCH=1`) | 0 / 3 |
| только `math::TraceVector` | 0 / 4 |
| только / вкл. `core::Report` | 5 / 10 |

Проверено и исключено:
- замена `Report` ни разу не вызывалась (лог входа пуст во всех запусках);
- переходов внутрь тела функции нет, указателей на неё в данных нет, все 451 ссылка — `call` на начало;
  `FUN_1063c340` вызывается только из неё;
- второй процесс игра не запускает (один PID в логе);
- общая проверка целостности кода маловероятна (хук `TraceVector` не вызывает эффекта).

Не объяснено. Хук выключен по умолчанию (`enabled=false`) до появления стека потоков в момент
ожидания (`winedbg --command "bt all"`, скрипт в истории сессии) или дифференциального теста с реальными вызовами.

Обновление: дифференциальный тест `core::Report` (36 проверок, 0 расхождений) подтверждает, что замена
повторяет поведение оригинала на 12 комбинациях аргументов и ответов VReport. Ошибка кодирования JMP, найденная
при написании трамплинов, касалась только нового кода (`WriteJump` в буфер), старая установка хука считала
смещение верно, так что #1 она не объясняет. Хук по-прежнему выключен до стека потоков в момент ожидания.

Обновление (13 хуков): ожидание снова появилось (2 сообщения за 90-секундный запуск), та же секция `11315750`,
ожидающий поток `0164`, держатель — главный поток. Секцию используют только функции модуля главного цикла движка
(`0x1085f810`–`0x10861e20`, больше всего `FUN_10860890`, 734 байта). Прежние сравнения шли по 75 с, а ожидание
видно только если оно длится ≥ 60 с — выборка могла быть смещена длительностью. Перепроверка: по 3 запуска
по 90 с без хуков и со всеми хуками.

**Закрыто.** Сравнение запусков одинаковой длины (по 90 с): без хуков ожидание появилось в 1 из 3 запусков
(2 сообщения), со всеми 13 хуками — 0 из 3. Это поведение самой игры под Wine: главный цикл держит секцию,
пока стоит меню. Прежняя корреляция с хуком `Report` возникла из-за сравнения запусков разной длины (75 и 90 с).
Хук `core::Report` включён снова: дифтест 36/36, игра работает до меню.
